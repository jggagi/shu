# 支线事件链：养成模式内的接入

用于 tea 等多阶段支线。活动、人物互动或固定场景热点进入事件；事件可以切换固定背景、调查物件、阅读文书或呈现短回忆，结束后继续养成。本文是设计，新增运行能力尚未实现。

## 最小能力与状态

| 能力 | 接入方式 | 状态要求 |
| --- | --- | --- |
| 分阶段推进 | quest/stage ID、宿主前置与完成旗标 | 修炼、休息、次日和退出支线不清空已提交进度 |
| 触发 | 菜单、对话、热点统一路由已登记活动 | 进入与结算时重查条件；不编造未批准的日期门槛 |
| 调查物件 | 固定场景热点绑定稳定 object ID | 描述随已知信息变化；重访不重复结算 |
| 阅读 | 登记 document cue，等待继续/关闭 | 打开不等于已取得线索或完成阶段；后期资料受条件限制 |
| 场景/短回忆 | 登记 profile/memory cue，保留返回上下文 | 不改变主角身份或自动推进养成时间；退出恢复原面板 |
| 一次完成 | 宿主白名单行动提交旗标与必要结果 | save/run + quest + stage 唯一键，换会话也不重复发奖 |

继续用 `say / choice / cue / end` 四类节点。表现 cue 不修改剧情旗标；需要确认的阅读等待玩家继续，取得线索与完成阶段由明确宿主行动提交。取消保留已提交线索，释放占用，不完成条件未满足的阶段。

进度包含旗标、事件节点、已取得线索和返回上下文。正文阅读位置与线索取得须分开定义。存档落地时与养成状态/回执一起保存；尚无存档时只承诺当前运行内保持。新周目/明确重置与普通休息、次日和退出事件必须区分。

## tea：《两盏茶》

已核对历史原稿 `jggagi/shu/story/sub/tea/README.md`，最后修改文件的 commit 为 `086e13eb11bd3710e2b7f8daa1c617c1d386be2c`。剧情方向已确认、尚未实现。本轮扩充 skill 的支持范围，不将完整支线自动排入 demo。

新支线原稿仍进入 `jggagi/sub`；tea 历史原稿保持原位置。实际接入记录来源，不将整篇原稿复制到 skill，也不自行迁移。阶段和来源 hash 见 [tea 适配样例](../assets/tea-chain.example.json)：它是接入计划，不是当前游戏能直接加载的文件。

必须保留：

- 入口名《归剑问天》，结尾才改名《两盏茶》；江砚秋是见证者，不绑定身世或主线谜团。
- 按原稿 A–I 推进：先相信痴情传说，再由日期、医案、信件、短回忆和公文重构理解，不能提前展示最终公文。
- 顾青萝主动提出未来不应被要求继续爱；谢长安从证明过去转向尊重选择。她不恢复记忆，他不复活，不新增幕后恶人。
- 开头两只杯子都可调查；结尾复用同一剑坪和同一物件 ID，改变描述并出现“添茶”。
- 添茶保留沉默与环境余韵，不加幻影、闪回合集、主题总结或强力装备奖励。“收起空杯”是否保留是待定项，不能强制。

场景可用山路、剑坪、问天峰旧院的固定背景与热点表达访问，不要求先实现自由行走。顾青萝与谢长安是前代人物，其正式角色 ID、立绘、回忆形式按实际制作登记；不替换现有师徒群像，不假称素材就绪。

茶杯调查可以没有属性收益。日期门槛、时间/精力规则和阶段完成所需的线索组合由实施任务卡明确；不强行发修为奖励来套养成循环。

## 一轮验收

选定一个阶段，列出可见线索、不可提前透露的信息、场景/物件和返回位置。交付“进入 → 调查/阅读 → 结束 → 继续养成”的小片段，再按试玩反馈接后续阶段。

检查早期入口无剧透、两杯可点、阅读/回忆可取消并返回、重访不重复结算、已完成阶段不重发奖励、休息/次日保留进度。存档实施后再验证恢复节点与返回场景。完整结尾额外核对同一茶杯 ID、后期描述、添茶沉默与标题变化。
