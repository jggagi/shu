## 养成画面的视觉要求

已查看参考截图：中央固定背景，主角与师傅在前景交谈，周边显示人物状态／日期／养成信息，底部承载对话。借鉴的是画面组织和互动感。

- 固定场景作为画面主体；人物、状态和对话随行动更新，师傅互动保持在同一养成场景中。
- 宋式建筑、器物与服饰气质；中国画的留白、山石竹木和克制用色；主角与师傅为有表情的 Q 版人物。
- 信息可读、交互区域明确。面板比例、人物位置、字体大小与色彩细节由 Codex 根据试玩反馈调整，再由用户拍板。
- 首轮可使用原创占位背景与人物。正式背景、角色和 UI 应在构图确认后统一制作；参考截图本轮未作为游戏素材导入仓库。

首场景暂提案为蜀山门内院落／修炼处。场景名称、屏幕比例、面板尺寸、具体宋式元素属于排版提案，尚未拍板。美术的宋式方向不额外确定故事的历史年代。

## 首场景需要支持的复用方向

先用一个场景检验：行动选择、短对话、时间与养成状态的可见反馈。具体属性、消耗与数值是 demo 参数，不作为已确认的完整游戏规则。

布局参数、人物资料、行动效果和对话内容应能独立调整。等第二个行动或人物真正复用时，再提取共用结构；不提前建通用编辑器或大型框架。

## 待定项

- 人物详细设定、门派名称、完整故事与世界观边界。
- 首场景最终排版、正式美术样张、屏幕适配范围。
- Godot 的具体稳定版本、正式属性与时间规则、存档方案。
- Web 首发内容量及发布方式；后续 Steam 的具体范围与发布安排。

新增决定先写明来源与状态；用户确认后更新本规格与决定日志。
