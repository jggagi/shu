# 码头：画稿与实时人物的空间适配

只在制作固定画景中的可走人物、局部灯火或投影时读取。以下是shu柳岸的已实现案例，不是新的通用渲染合同。整体流程与下一片简报见[城镇制作方法](../../../../docs/PAINTED_TOWN_PRODUCTION_METHOD.md)。

## 先把空间标在原画上

本片原画1536×864，逻辑画景1280×720；茶棚、干岸、石阶、船与水面先形成完整构图。独立[布局](../../../../assets/data/dock-corner-layout.json)标出凹多边形走区、实体障碍与物件接近点；图像像素、逻辑画景、显示窗口、3D世界坐标不同，不能直接混用。

[Walker](../../../../addons/cultivation_mode/dock_corner_walker.gd)中人物使用透明3D SubViewport、固定正交相机；本片80像素／世界单位、45度俯角。固定投影允许在相机尚未进入树时安全计算锚点，避免初始化阶段直接unproject失败。另一幅图的角度、地平线、人物比例与投影需要重新标定，不能直接复制数值。

先在实际窗口放一个站立人物，检查脚底、建筑根部和台阶，再画障碍与阴影mask。二维台阶并不因此成为三维台阶；本片用局部受影范围适配，不声称完整墙体、台阶或服饰几何投影。

## 图层次序必须经遮挡验证

本片由远及近：画稿与水面 → 柔和人物影 → 人物／猫的共同深度通道 → 原柳树前景裁层 → 涟漪反馈 → 世界调色 → 灯火叠加 → 热点；对白等UI不受世界调色。实际节点与合成以代码为准，不要求其他场景照搬全部层。

猫曾在2D覆盖层经过前方人物，像骑到头顶；改用Sprite3D放入人物深度通道解决本例。增加2D的z_index不能自动获得与3D人物的前后关系。至少检查人物前／后经过一次、动物和人物重叠一次、前景遮挡一次；关闭单个贡献层做对照可以定位错误。

## 光源、受光与影子需要指向同一实物

[时辰配置](../../../../assets/data/dock-corner-time-light.json)提供清晨、午后、黄昏、月夜手动预览，默认保留用户喜欢的午后；这些预览没有扩展宿主时辰。画景调色、人物光色和局部灯光协调，别用全屏提亮替代实际灯位。

[灯位](../../../../assets/data/dock-corner-lamps.json)对应茶棚檐灯和船灯，协调可见灯火、人物暖光、地面光池和水面反射。白天关闭、黄昏减弱、月夜完整只是本片参数。闪烁和水面使用受控相位；静景、菜单能冻结相应表现。

[人物投影](../../../../addons/cultivation_mode/dock_corner_shadows.gd)按姿态骨段形成柔和轮廓，投到布局导出的干岸／石阶mask，并与原脚底接触影配合。灯影响连续混合，避免经过边界突然换影向。透明3D接收面实验未得到可见轮廓，最终采用画景局部合成；技术路线以可见收益决定。帽子、竹篓和建筑的完整物理投影尚未实现。

## 迁移时的最小对照

选一个落脚点，在同一宿主状态对照：原画光／新光、人物影关／开、静景／动态；再看夜灯附近和无灯区域。检查脸部、衣物、地面、UI是否各自清楚，阴影是否越出干岸，恢复动态是否跳变。代码通过、截图观察与用户认可分别记录。这里的方法不证明连续大城的接缝、内存或帧率可接受，后者另作实际场景验证。
