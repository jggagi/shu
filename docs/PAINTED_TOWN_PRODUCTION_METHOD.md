# 绘景城镇切片制作方法

2026-11-13，依据柳岸码头0.2.7及其前序切片整理。用户对当前底部头像对话栏反馈「很好」，要求沉淀方法与skill，为后续铺开准备。本轮只整理方法和项目内skill；没有开始全城改造。各历史切片的构建、原生观察、浏览器实操和用户认可仍分别记录。

## 从样片得到的判断

原大城解决了尺度和连通，但道路偏宽、建筑重复、建筑与地面脱节，让大量细节难以形成完整画面。独立码头先统一构图、材质笔触、岸线和建筑接地，再叠加人物、灯火与生活动作，获得更明确的积极反馈。后续复用这种制作次序；不据此推定固定码头的一张画可直接覆盖整座连续跟随的大城。

当前方法是画稿主导的混合场景：画稿承担主要空间和生活细节，少量实时人物与动物提供行走、遮挡、受光和互动，导航与物件锚点单独配置。二维画稿中的台阶、墙和屋檐不会自动产生三维碰撞或投影。要逐处补真实需要的关系，并在实际游戏窗口观察。

## 一片的制作顺序与退出条件

| 阶段 | 需要做出的结果 | 进入下一步前看什么 |
| --- | --- | --- |
| 场地简报 | 镜头、主视觉、可走区、入口／出口、一个可做的事 | 能说明玩家来到这里会看什么、走到哪里、做什么 |
| 静态画稿 | 建筑、窄巷／岸线、地面材质与少量生活道具形成完整构图 | 实际人物尺度放入后，建筑落地、道路宽度和阅读空间成立 |
| 空间适配 | 走区、障碍、接触点、前景遮挡与人物投影 | 行走不穿墙入水，人物脚不浮，前后经过不会出现画卡盖头 |
| 光与环境 | 默认午后，再按需求加入其他光景、局部灯火和少量动态 | 世界与人物受光一致；夜灯有实物光源、附近受光及适当倒影；UI可读 |
| 生活与动作 | 少量有差异的路人／动物，以及一个行动→结果回路 | 轮廓和姿态在小窗口可辨，路线确实会动，动作接触与结果时机一致 |
| 叙事界面 | 当前人物头像、姓名、台词、原选项／继续 | 切人同步，旁白不借头像，菜单优先，旧回调不推进新事件 |
| 交付与反馈 | 可对照的试玩、来源与分层验证记录 | 区分技术通过、真实观察、用户接受与尚未验证的范围 |

这不是每片必须重做七步。新增一盏灯或改字号只检查受影响关系；已经成立的画稿与素材优先复用。先交付小片让用户看见效果，再决定新增层或抽取共享实现。

## 把可复用部分和场景制作分开

| 层面 | 可以复用 | 每片需要重新制作／判断 |
| --- | --- | --- |
| 玩法 | 现有EngineSession、操作身份、一次结算、存档与返回路径 | 既有玩法中的物件、条件、费用和剧情来源 |
| 空间 | 原有导航及角色适配方法 | 原画坐标、干岸／台阶mask、障碍、脚底、入口、对象接近点 |
| 光景 | 观察宿主状态、受控表现时钟、世界与UI分离 | 光源实物位置、阴影方向、材质受光、灯池与水面反射范围 |
| 生趣 | 固定种子机会边界、当前点暂停与恢复、角色深度通道 | 栖地能力、路径、初始距离、轮廓配件和停留姿态 |
| 对话 | 当前event_view、稳定speaker ID、原选择／继续回调 | 头像来源与裁区、排版、旁白样式、遮罩层级 |

布局、表现参数和玩法内容分别保存。先检查现有adapter；只有第二个真实用例证明边界相同时，再提取共用结构。现有码头代码是实现参照，不是需要复制整套的模板。

## 三个需要显式写下的合同

**状态与时钟。** Session决定剧情、时间、精力与结算。画景、阴影、路人和对白展示只观察；光景手动预览不推进游戏时辰，月夜预览不增加钟槽。表现时钟由场景控制，要求冻结的shader不能自己使用独立TIME。

**暂停与占用。** 本片静景冻结环境与居民机会／行程；对话让居民在当前位置安静站定或坐下。已选择且已结算的投石在静景下完成收势；菜单／确认暂停它。不要把“动态关”扩写为所有动作停摆。新片按实际交互明确自己的暂停表，复用时保留原合同。

**事件与身份。** 头像、名字、台词来自同一当前事件节点；展示不另起对白游标。选择复用原操作ID，继续保留run／revision检查。前台动作按出手、落水等真实时机展示反馈，收势前保护继续入口。读档／重开清理临时动作和声音，不重复结算或补播过期提示。

## 来源和美术制作

先检查当前人物身份、已选画稿和既有头像。新头像的身份参考与风格参考分开：本次男茶商从当前模型离线取景，两张原人物画仅提供风格；另一位女茶商的图不能通过改名成为该人物。记录准确prompt、模型、输入、选用原图、裁区、SHA256和使用条款。已选百炼模型与现有凭据接入继续沿用，制作批次和生图次数遵循当轮授权。

原图、候选与运行时裁区分离。本次头像底部意外文字框可以在不损失头像的条件下被裁区排除；身份错、五官损坏或主体被切断不能靠裁区宣称修好。素材原图与运行时截图都要看，模型导入成功不代表alpha、构图或落地成功。

## 铺开前的一片简报

下一片先填下面这些实际信息即可，不另建大框架。地点尚未指定，下表为制作提案，不是已开工任务。

| 项目 | 要填写的内容 |
| --- | --- |
| 地点与镜头 | 所选街角／相邻空间；固定画景还是连续镜头；邻接方向与返回点 |
| 原有素材 | 选用画稿、人物和来源；还缺哪一项；是否需要新生图 |
| 空间锚点 | 可走面、障碍、建筑接地、遮挡边、实际物件与人物接近点 |
| 主视觉与光 | 默认光景、一个值得观察的变化；夜景有无真实灯位 |
| 生活层 | 有依据的栖地／路人路线、初始点、差异轮廓与静止姿态 |
| 玩家行为 | 一个已有宿主支持的行动、代价／结果、对白与返回路径 |
| 暂停与输入 | 动态关、对话、菜单、读档、重开时分别发生什么 |
| 可见验收 | 同尺度截图、一次行动→结果、说话人／旁白、遮挡、暂停恢复 |

建议先用一个相邻小空间验证这套方法能否迁移：先确定入口和两边的画风／尺度，再完成同一质量的小片，随后检查切换或连续镜头的接缝、遮挡与性能。固定画景切换和全城连续跟随是两种适配问题；当前大城连续跟随要求仍保留，具体接入方案和第二片地点待下一轮确定。不要先批量生完整街区，再发现投影与接缝不成立。

## 验收与当前证据

新片按改动范围检查实际窗口里的脚底、前后遮挡、光色、文字和点击；动作有结算时验证一次行动→结果、拒绝／重试、取消、读档及重开。需要导出时保留源输入摘要、冻结产物和实际加载结果，防止用旧包截图说明新源码。纯文档／skill维护只验证文档链接、结构和diff，不重新构建游戏。

柳岸0.2.7交付时：X1 Fedora，Godot4.7.2、Compatibility，HEAD `7c992c578b1fe4a1624c769812425b38080771d3`，工作区dirty。296项宿主检查；1152×720和960×600共1002项原生检查及76图；Web导出、导出PCK原生加载、7文件HTTP一致性通过。用户随后对底部对话结果反馈「很好」。这些证据不等于浏览器刷新／真实输入、设备音效、Windows／Steam Deck或性能已验收，也不等于其他街区获批准。[当前对话任务卡](DOCK_CORNER_DIALOGUE_SLICE.md)保留完整证据路径与历史状态。
