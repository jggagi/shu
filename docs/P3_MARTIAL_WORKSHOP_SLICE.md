## 数据、制作与运行边界

[六招配方](../assets/data/martial_workshop/recipes/)、[固定骨架profile](../assets/data/martial_workshop/profiles.json)与[编译目录](../assets/data/martial_workshop/catalog.json)分开管理。配方说明动作模板、腕轨迹／身体关键帧、源秒映射、特效、声音与镜头；profile声明原模型、22骨架、手型和掌／剑锚点。新增三招分别有独立编排和动作GLB。

离线[批处理器](../tools/build_martial_workshop.py)先检查整批，再复用三个既有动作或调用本地[动作编译器](../tools/hero_lookdev/build_workshop_motions.py)导出三招新动作。输入指纹包含配方、profile、资源与工具源码／可执行文件SHA；命中缓存仍检查产物字节。每任务保留manifest，新动作另有source-motion、可编辑Blend位置、来源和许可；原模型与既有动作只读。精确字段、坐标、模板约束和来源见[制作说明](../assets/data/martial_workshop/README.md)，应用与资产绑定见[本轮来源](../assets/data/martial_workshop/source-workshop.json)。

```bash
python3 tools/build_martial_workshop.py --check-only
python3 tools/build_martial_workshop.py
python3 tools/build_martial_workshop.py  # 同输入再次执行检查缓存
```

新配方用全新ID／clip，可通过`--recipes-dir`和`--output`在独立目录试制；无需增加招式ID的播放器分支。自定义输出不替换应用六招目录，外部包的资源路径按制作说明提供。当前支持两个固定22骨架，以及剑轨迹、横掌、立掌三个模板；开放左掌沿用固定手型，没有独立指骨。新增武器、不同骨架或新动作语法仍需补真实模板和验证。

[统一播放器](../addons/cultivation_mode/martial_move_player.gd)用一个时钟推进身体、真实锚点、特效、局部灯和音效；[绑定器](../addons/cultivation_mode/martial_actor_binding.gd)检查骨架／rest／动画并映射轨道。[工坊UI](../addons/cultivation_mode/martial_workshop_view.gd)只接收宿主对局快照副本，独立Stage及SubViewport呈现，关闭时停止试演并释放视口；不新建EngineSession或Rules，不提交行动或修改宿主存档。

审阅存于`user://martial_workshop/reviews.json`，与游戏进度分开，绑定目录及资产SHA。原生与Web使用各自存储；Web还取决于浏览器与站点来源，不承诺跨入口同步。目录变化令本批回待审，保存新批时保留旧意见；损坏的原记录报告错误并停止覆盖。Web只读取已编译批次，页面没有「生成」按钮。声音沿用已有原创短声与招式声开关；调度可检查，设备听感另验。

## 下一验收点

1. 在960和1152完整界面中看清人物与招式，六招可以按两类／两风格筛选，文字和操作不互相遮挡。
2. 新三招的发力方向、身体姿态与收势可区分；掌风与斩弧跟随实际出手，慢放／拖动后不与身体脱节。

4. 上一招对照可以反复交换；退回空白原因被拒绝，有效意见重开可见，资源更新后回到待审。
5. 离线重跑同配方命中缓存，错误资源／时间轴／骨架在生产前被拒绝；新增第七个测试配方可独立编译而不替换正式六招。

自然的动作编排、角色辨识度、门派气质和战术平衡仍需作者与玩家判断。后续先根据六招实景审阅修订动作，再为拳、刀、棍、腿各补一个有区别的模板与实际用例，不把所有类别／门派／特效直接全排列。
